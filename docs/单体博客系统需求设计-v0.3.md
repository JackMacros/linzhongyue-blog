# 林中月单体博客系统需求设计（v0.3，最终确认稿）

> 文档状态：已批准，2026-08-04 开始实施  
> 编写日期：2026-08-04  
> 约束：用户确认整体需求之前，不创建或重构业务代码。

## 1. 项目背景

当前系统由三部分组成：

1. 博客前台 `frontend`：React + TypeScript + Vite，提供首页、博客、文章详情、专栏、关于和联系页面，当前使用本地静态数据。
2. 博客管理端 `app`：React + TypeScript + Vite，提供仪表盘、文章、标签、专栏以及一组系统管理页面，当前使用本地 Mock 数据。
3. 旧后端 `blog-api`：Spring Boot 多模块项目，共 7 个 Maven 模块、约 263 个 Java 文件，包含博客、权限、Redis、文件、AI、Quartz、代码生成、监控、评论、留言、相册、友链等大量能力。

旧后端是“通用后台管理系统 + 博客”的大而全架构，与当前个人博客的实际需求不匹配。新系统目标是重新建设一个单模块、单进程、单 Jar 的 Spring Boot API，并让两个独立部署的前端接入真实 API。

## 2. 已确认的现状

### 2.1 旧后端技术栈

- Java 21
- Spring Boot 3.5.5
- Spring MVC
- MyBatis-Plus 3.5.9
- MySQL 8
- Druid 数据源
- Sa-Token 1.40
- Redis
- Lombok
- Springdoc/OpenAPI
- Spring AOP
- Flexmark + Jsoup
- MinIO、七牛云
- Quartz
- Spring AI / DashScope

### 2.2 旧后端复杂度来源

- 采用 `common/admin/auth/file/quartz/ai/server` 7 模块结构，但最终仍打成一个进程，模块成本大于实际收益。
- 包含评论、留言、说说、友链、相册、通知、动态菜单、字典、代码生成、服务器监控、在线用户、定时任务等当前前台未使用功能。
- 文章表包含 AI 摘要、评论数、原创/转载、置顶、评论开关、冗余分类名、逻辑删除、Markdown 与 HTML 双份内容等字段。
- 专栏与文章使用中间关系表，但当前前台业务实际上是一篇文章最多属于一个专栏。
- 标签、分类保存冗余文章数量，需要额外维护一致性。
- 浏览量依赖 Redis，再由异步逻辑维护，个人博客场景可先直接使用数据库原子更新。
- 旧项目没有版本化 SQL 建表脚本和有效的自动化测试。

### 2.3 前台实际需要的数据

当前公开站点的文章模型包含：

- 唯一 `slug`
- 所属专栏
- 分类
- 中英文标题
- 中英文摘要
- 发布日期
- 阅读时间
- 多个标签
- 中英文正文及目录

当前公开站点没有评论、用户注册、留言、友链、相册、说说等入口。

### 2.4 管理端现状

- 桌面端视觉完整，文章、标签、专栏的本地 CRUD、查询和分页可用。
- 没有登录页、鉴权状态和 API 层。
- “写文章”只有列表元数据，没有 slug、摘要、正文和双语内容，不能真正完成文章创作。
- 用户、角色、字典、参数、菜单等部分按钮只是演示占位。
- 390px 移动端下固定侧栏会导致页面总宽超过 1000px，管理端移动端不可用。

## 3. 建设目标

### 3.1 核心目标

1. 建设一个单 Maven 模块、单 Spring Boot 进程的博客后端。
2. 一份 MySQL 数据成为前台与管理端的唯一数据源。
3. 保留现有前台和管理端的视觉设计，补齐真实数据与完整交互。
4. 管理员能够登录并完成文章、标签、专栏的真实管理。
5. 前台能够读取已发布文章，完成搜索、筛选、详情、专栏和中英文切换。
6. 公开前台、管理端和后端分别构建，由 Nginx 托管静态资源并反向代理 API。
7. 数据表和业务字段只保留当前产品真正需要的内容。

### 3.2 非目标（推荐删除）

以下功能默认不进入第一版：

- 前台用户注册和登录
- 评论与评论审核
- 留言、说说、友链、相册、通知公告
- 多租户
- 工作流和文章审核流
- 动态菜单、按钮级权限、字典管理
- 代码生成器
- 服务器、JVM、Redis 在线监控
- 在线用户管理
- Quartz 定时任务
- AI 自动摘要与内容审核
- 七牛云双存储适配

## 4. 推荐总体架构

### 4.1 仓库和部署形态

已确认采用“两个独立前端 + 一个单模块后端 + Nginx 统一入口”：

```text
linzhongyue-blog/
├─ pom.xml
├─ src/main/java/com/linzhongyue/blog/
│  ├─ BlogApplication.java
│  ├─ common/
│  ├─ config/
│  ├─ auth/
│  ├─ article/
│  ├─ column/
│  ├─ tag/
│  ├─ dashboard/
│  ├─ log/
│  └─ file/
├─ src/main/resources/
│  ├─ application.yml
│  ├─ application-dev.yml
│  ├─ mapper/
│  └─ db/
├─ frontend/             # 现有公开博客 React 项目，独立构建 dist
└─ app/                  # 现有管理端 React 项目，独立构建 dist
```

推荐生产部署：

- Nginx 托管公开博客 `frontend/dist`。
- Nginx 单独托管管理端 `app/dist`，可使用 `/admin/` 路径或独立子域名。
- Nginx 将 `/api/**` 反向代理到 Spring Boot。
- Spring Boot 仅提供 API 和后台任务，不托管两个前端构建产物。
- 后端自身仍为单 Maven 模块、单 Jar、单进程。

前端继续使用 HashRouter，可降低 Nginx 路由回退配置复杂度。生产环境推荐公开站点使用主域名、管理端使用独立子域名，两个站点都通过各自同源的 `/api` 反向代理到同一个 Spring Boot 服务，因此浏览器侧不需要跨域。开发环境只放行明确的本地前端地址。

### 4.2 Java 包结构

不再拆 Maven 子模块。单模块内部采用“按业务功能分包”，每个功能包含自己的 controller、service、mapper、entity、dto、vo：

```text
article/
├─ ArticleController.java
├─ AdminArticleController.java
├─ ArticleService.java
├─ ArticleMapper.java
├─ Article.java
├─ dto/
└─ vo/
```

这种结构保持单体简单，同时避免所有 Controller、Service、Mapper 分散在全局目录中。

| 技术 | 删除原因 |

### 5.3 已确认的存储方案

- 图片统一上传七牛云，由七牛云 CDN 承担图片访问流量。
- 删除 MinIO 和本地业务图片存储实现。
- Redis 已确认作为正式基础设施，同时服务于 Sa-Token 会话持久化和热点内容缓存。
- 文章浏览量仍使用 MySQL 原子自增，每日 PV/UV 使用 MySQL 聚合表，避免引入 Redis 计数回刷的一致性复杂度。

### 5.4 Redis 与缓存边界

Redis 不作为业务数据源，MySQL 始终是文章、标签、专栏、站点内容和统计数据的最终事实来源。Redis 只承担两类职责：

1. 保存 Sa-Token 登录会话，使应用重启后管理员登录状态可以继续有效。
2. 缓存高频公开查询，减少重复查询和 Markdown 大正文的数据库读取。

第一版建议缓存：

| 缓存内容 | 建议 TTL | 失效时机 |
|---|---:|---|
| 文章详情 `blog:article:detail:{slug}` | 30 分钟 | 文章编辑、发布、下架、删除或 slug 修改 |
| 文章列表、搜索结果和最新文章 | 5 分钟 | 任意文章创建、编辑、状态变更或删除 |
| 标签列表 | 30 分钟 | 标签或文章标签关系变更 |
| 专栏列表和详情 | 15 分钟 | 专栏或专栏内文章变更 |
| 首页、关于、联系站点内容 | 30 分钟 | 对应内容保存后 |
| 管理端仪表盘摘要 | 1 分钟 | 文章或统计数据变更，也允许等待短 TTL |

缓存键必须带统一前缀和结构版本，避免将来字段调整读取旧数据。文章 slug 修改时同时清除旧 slug、新 slug、文章列表、最新文章、相关标签和专栏缓存。站点内容、标签、专栏以及七牛云素材修改后清理对应缓存。

公开内容缓存读取异常时自动回源 MySQL，不允许因为 Redis 缓存故障导致公开博客整体不可访问；Redis 恢复后再自然回填。Sa-Token 会话本身依赖 Redis，因此 Redis 故障期间管理端登录和鉴权可以返回明确的 503，生产部署需要为 Redis 配置持久化、密码和健康检查。

文章浏览量不放入 Redis 延迟回刷，而是由 MySQL 执行原子自增；详情正文可以缓存，但浏览量上报使用独立接口，详情响应不承诺每次都展示刚刚自增后的实时数字。第一版因此不需要 Quartz 或浏览量回刷任务。

## 6. 功能需求

### 6.1 公开博客前台

#### 首页

- 保留现有 Hero、精选项目和最新文章视觉。
- 最新文章从 API 获取最近发布的 3 篇。
- 精选项目、个人简介和联系方式从站点内容 API 获取；纯 UI 文案继续由前端 i18n 管理。

#### 博客列表

- 只展示 `PUBLISHED` 状态文章。
- 支持分页。
- 支持标题和摘要关键字搜索。
- 支持标签、专栏筛选。
- 支持中英文展示。

这里的“中英文展示”仅指导航、按钮、提示、页脚等站点框架文案。文章标题、摘要和正文只保存一套原始内容，切换语言后文章内容不翻译。

#### 文章详情

- 使用 slug 访问，例如 `/blog/agent-orchestration-patterns`。
- 展示标题、摘要、标签、专栏、发布日期、阅读时间和正文。
- API 返回 Markdown 原文，公开 React 前台负责 Markdown 渲染。
- Markdown 支持 GFM 表格、任务列表、删除线、链接、引用和围栏代码块。
- 代码块支持语言识别、语法高亮、横向滚动和一键复制。
- 前端根据 Markdown 标题生成右侧目录和标题锚点。
- 展示相同标签或专栏的相关文章。
- 详情页加载后单独上报一次浏览量。

#### 专栏

- 展示专栏名称、简介、状态、文章数量和最近更新时间。
- 专栏详情按发布时间倒序展示已发布文章。
- 一篇文章最多属于一个专栏，文章也可以不属于任何专栏。

#### 首页、关于和联系

- 已确认需要在后台编辑。
- 可编辑内容至少包括个人名称、身份介绍、个人简介、邮箱、社交链接、精选项目、经历时间线、技能和首页/关于/联系页的业务文案。
- 导航、按钮名称、表单提示等纯 UI 文案仍保留在前端 i18n 文件中，不进入数据库。
- 以上用户可编辑的公开业务内容保存中英文两套；导航、按钮和校验提示等纯 UI 文案仍由两个前端的 i18n 文件管理。

### 6.2 管理端

#### 管理员认证

- 提供登录、登出、查询当前管理员接口。
- 使用用户名和 BCrypt 密码登录。
- 使用 `sa-token-spring-boot3-starter`，并通过 `sa-token-redis-jackson` 将会话持久化到 Redis。
- 生产环境管理端通过自身同源的 `/api` 代理访问后端，Token 使用 `HttpOnly + Secure + SameSite=Lax` 的主机级 Cookie，不向公开站点域名发送。
- Sa-Token 保护所有 `/api/admin/**` 接口。
- 已确认只有一个管理员，不建设 RBAC、动态菜单和按钮权限。

#### 仪表盘

- 文章总数、已发布数、草稿数、标签数、专栏数。
- 文章总浏览量。
- 最近 7 天 PV 趋势（如果确认保留访问统计）。
- 热门文章 TOP 5。
- 最新草稿。

#### 文章管理

- 文章分页、搜索、按发布状态/专栏/标签筛选。
- 新建、编辑、删除文章。
- 草稿和发布状态切换。
- 编辑字段：slug、标题、摘要、Markdown 正文、专栏、标签、发布日期。
- 自动根据 Markdown 正文计算预计阅读时间。
- slug 必须唯一，仅允许小写字母、数字和连字符。
- 删除采用物理删除；删除文章时同步删除文章标签关系。
- 第一版不做置顶、审核流、转载、评论开关、AI 摘要。

#### 标签管理

- 标签列表、新增、编辑、删除。
- 字段：名称、颜色。
- 文章数量实时聚合查询，不保存冗余 `article_count`。
- 已被文章使用的标签删除前必须明确提示；确认后删除关系。

#### 专栏管理

- 专栏列表、新增、编辑、删除。
- 字段：slug、中英文名称、中英文简介、连载状态、排序。
- 文章数量和最近更新时间实时聚合，不保存冗余字段。
- 删除专栏后，其文章的 `column_id` 置空，不删除文章。

#### 个人中心

- 修改昵称、邮箱、头像。
- 修改密码时校验旧密码、新密码长度和两次输入一致性。

#### 站点内容管理

- 提供首页、关于、联系三个分区的编辑表单。
- 支持管理精选项目、经历时间线、技能和社交链接等重复列表。
- 不建设通用字典或任意 key/value 参数平台，使用固定 DTO 和固定表单，保证字段可校验。

#### 日志

- 操作日志默认保留精简版，用于记录文章、标签、专栏和账号修改。
- 已确认删除详细访问日志页面，只保留每日聚合和文章浏览量。

### 6.3 默认从管理端移除的页面

- 用户管理
- 角色管理
- 字典管理
- 参数管理
- 菜单管理
- 访问日志
- 服务器/缓存/在线用户管理

管理端侧栏默认精简为：仪表盘、文章管理、标签管理、专栏管理、站点内容、操作日志、个人中心。

## 7. 推荐数据库设计

第一版确定使用 13 张精简业务表：管理员、文章、专栏、标签及关系、5 张固定站点内容表、七牛云素材、操作日志和每日聚合统计表。不建立角色、菜单、分类、评论、访问明细或通用配置表。

### 7.1 `admin_user`

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT | 主键 |
| username | VARCHAR(50) | 登录名，唯一 |
| password_hash | VARCHAR(100) | BCrypt 密码 |
| nickname | VARCHAR(50) | 昵称 |
| email | VARCHAR(100) | 邮箱，可空 |
| avatar_url | VARCHAR(500) | 头像，可空 |
| enabled | TINYINT | 是否启用 |
| last_login_at | DATETIME | 最后登录时间，可空 |
| created_at | DATETIME | 创建时间 |
| updated_at | DATETIME | 更新时间 |

删除旧用户表中的手机号、性别、登录方式、IP、属地、系统、浏览器等非核心字段。第一版不创建角色、用户角色、菜单权限表。

### 7.2 `blog_article`

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT | 主键 |
| slug | VARCHAR(160) | URL 唯一标识，唯一索引 |
| title | VARCHAR(255) | 文章标题 |
| summary | VARCHAR(1000) | 文章摘要 |
| content | LONGTEXT | Markdown 原文 |
| column_id | BIGINT | 所属专栏，可空 |
| status | VARCHAR(20) | `DRAFT` / `PUBLISHED` |
| published_at | DATETIME | 发布时间，可空 |
| view_count | BIGINT | 浏览次数，默认 0 |
| read_minutes | INT | 预计阅读时间 |
| created_at | DATETIME | 创建时间 |
| updated_at | DATETIME | 更新时间 |

删除旧文章表中的 `ai_summary`、`comment_counts`、`content_html`、`cover_image`、`original_link`、`font_counts`、`is_original`、`is_weight`、`is_comment`、`is_deleted`、分类 ID 和冗余分类名称等字段。

正文 HTML 不落库，API 返回 Markdown 原文。公开前台使用 React Markdown 渲染，默认禁止 Markdown 中的原始 HTML；目录由 Markdown 标题生成，不单独保存 headings 数组。

### 7.3 `blog_column`

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT | 主键 |
| slug | VARCHAR(120) | 唯一标识，唯一索引 |
| name_zh | VARCHAR(100) | 中文专栏名称 |
| name_en | VARCHAR(100) | 英文专栏名称 |
| description_zh | VARCHAR(1000) | 中文专栏简介 |
| description_en | VARCHAR(1000) | 英文专栏简介 |
| status | VARCHAR(20) | `ONGOING` / `COMPLETED` |
| sort_order | INT | 排序 |
| created_at | DATETIME | 创建时间 |
| updated_at | DATETIME | 更新时间 |

删除封面、精选、上架开关、冗余文章数量。删除原 `blog_column_article_relation`，在文章表直接保存 `column_id`。

文章正文只保存一套原始内容；专栏名称和简介属于站点导航与组织信息，为保持现有前台双语体验而保存中英文两套。

### 7.4 `blog_tag`

| 字段 | 类型 | 说明 |

## 8. API 设计草案

### 8.1 统一约定

- JSON API 前缀统一为 `/api`。
- 成功响应：`{ "code": 0, "message": "ok", "data": ... }`。
- 失败响应使用稳定业务错误码，并设置正确 HTTP 状态码。
- 分页响应：`{ "items": [], "page": 1, "pageSize": 10, "total": 0 }`。
- 时间使用 ISO 8601，例如 `2026-08-04T16:30:00+08:00`。
- 文章接口只返回一套文章内容；语言切换不重新请求或翻译文章。

### 8.2 公开 API

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/public/articles` | 文章分页、搜索、标签和专栏筛选 |
| GET | `/api/public/articles/latest` | 首页最新文章 |
| GET | `/api/public/articles/{slug}` | 文章详情 |
| POST | `/api/public/articles/{slug}/view` | 上报一次浏览 |
| GET | `/api/public/tags` | 标签列表 |
| GET | `/api/public/columns` | 专栏列表 |
| GET | `/api/public/columns/{slug}` | 专栏详情及文章列表 |
| GET | `/api/public/site-content` | 首页、关于和联系业务内容 |
| POST | `/api/public/visits` | 增加每日 PV/UV 聚合 |

### 8.3 认证 API

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/auth/login` | 管理员登录 |
| POST | `/api/auth/logout` | 登出 |
| GET | `/api/auth/me` | 当前管理员 |
| PUT | `/api/auth/profile` | 修改资料 |
| PUT | `/api/auth/password` | 修改密码 |

### 8.4 管理 API

| 模块 | 接口范围 |
|---|---|
| Dashboard | `/api/admin/dashboard/summary`、`/trend`、`/top-articles`、`/drafts` |
| Article | `/api/admin/articles` REST CRUD、`/{id}/status` |
| Tag | `/api/admin/tags` REST CRUD |
| Column | `/api/admin/columns` REST CRUD |
| Site Content | `/api/admin/site-content` 查询和保存站点内容 |
| Log | `/api/admin/operation-logs` 分页查询和清理 |
| Media | `/api/admin/media` 素材分页、`/images` 上传、`/{id}` 删除 |

不再使用 `GET` 修改状态或删除数据，所有写操作使用 POST/PUT/PATCH/DELETE。

## 9. 前端改造范围

### 9.1 公开前台 `frontend`

- 新增统一 API Client、请求错误处理和加载/空状态。

- 专栏和可编辑站点内容从 `i18n.tsx` 移至 API；纯 UI 文案继续留在 i18n。
- 文章列表、详情、首页最新文章和专栏页面接入 API。
- 使用 `react-markdown`、`remark-gfm`、`rehype-slug` 和代码高亮插件（`rehype-highlight` 或 Shiki）渲染 Markdown，并生成目录和复制按钮。
- 不接入 `rehype-raw`，`<iframe>`、自定义 `<div>`、`<script>` 等原始 HTML 一律按普通文本处理或过滤。
- 保留当前双语切换、动效和设计语言。

### 9.2 管理端 `app`

- 标签、专栏、站点内容、个人中心、仪表盘和日志接入 API。

## 10. 安全要求

1. 旧项目配置文件中存在明文数据库、Redis、对象存储及 AI 凭据；在继续开发前必须全部轮换。
2. 任何真实凭据不得进入 Git；配置使用环境变量，仓库只提交 `.env.example` 或占位配置。
3. 密码使用 BCrypt，不返回密码字段。
4. Sa-Token 仅保护 `/api/admin/**`，公开 API 明确放行。
5. 生产环境通过两个站点各自的同源 `/api` 代理访问；开发环境 CORS 只放行明确的本地端口。Cookie 认证的写请求校验 `Origin`，降低跨站请求风险。
6. React Markdown 默认禁止原始 HTML；链接、图片协议和目标地址需要白名单处理，防止存储型 XSS。
7. 所有 DTO 使用 Bean Validation；slug、分页大小、上传类型和文件大小必须限制。
8. 登录接口增加基础限流；第一版不强制图片验证码。
9. 操作日志不得记录密码、Token、正文或其他敏感请求体。
10. MySQL、Redis、Sa-Token、七牛云和允许来源均通过环境变量配置；生产环境不得使用示例默认值。

## 11. 初始化与数据迁移

已确认需要迁移旧 MySQL 中的文章内容，但不沿用旧表结构。迁移程序以只读方式访问旧库，只选择“已发布且未逻辑删除”的文章并写入新库：

- 标题、摘要、Markdown 正文。
- 原发布时间和更新时间。
- 原浏览量。
- 标签和专栏关系。
- 正文中已有的七牛云图片 URL。

草稿、已下架/未发布文章和逻辑删除文章全部不迁移。忽略 AI 摘要、HTML 副本、评论、评论数、转载信息、置顶、评论开关等旧字段。旧分类表不迁移；如果文章存在旧分类名称，则把该名称合并为普通标签，避免丢失原有组织信息。

迁移后的文章状态统一为 `PUBLISHED`。能复用且符合新格式、无冲突的旧 slug 则保留；当前前端已使用的固定文章优先沿用现有 slug；其余冲突或缺失 slug 使用稳定的 `article-{旧文章ID}`，后续可在管理端修改。旧专栏缺失时文章允许不属于专栏；同名标签和专栏先去重再建立关系。

迁移程序扫描 Markdown 中的原始 HTML。检测到 `<iframe>`、自定义 `<div>` 等内容时不启用 HTML 渲染，也不静默执行，而是输出“需人工复核文章”报告；正文原始数据保留，公开前台只按安全 Markdown/GFM 规则展示。正文和站点内容中的图片 URL 原样保留，可识别的七牛云对象同步登记到 `media_asset`。

迁移分为预检报告、测试库试迁移、数量/字段抽样核对和正式迁移四步；正式迁移前备份新库，迁移脚本设计为可重复执行且不会重复插入。

初始化脚本应包含表结构和开发种子数据。管理员初始密码通过环境变量或首次启动命令提供，不能硬编码到 SQL。
